# Schema 4 Lite 設計概要

## 目的

Gemini Nanoへ複雑な出典追跡や自由な最終文書生成を求めず、最大3案の比較・選択へ役割を限定する。

## 責務分担

| 処理 | Gemini Nano | JavaScript | ユーザー |
|---|---:|---:|---:|
| 緑案の発想 | ○ |  |  |
| 制約・対象外の一次評価 | ○ |  |  |
| 初期採否の算定 |  | ○ |  |
| 採否の確定 |  |  | ○ |
| 最終青コンテキストの構築 |  | ○ |  |

| 案名・概要・行動本文の保持 |  | ○ |  |
| 最終表示の組立て |  | ○ |  |

## 緑案の採否

各案は次の状態を持つ。

- `include`：最終青へ渡す
- `conditional`：条件付き候補として渡す
- `exclude`：最終青へ渡さない

初期状態は制約・対象外評価から決定する。

- `violates`または`conflicts`：`exclude`
- `unknown`または`possibly_conflicts`：`conditional`
- それ以外：`include`

ユーザーは初期状態を変更できる。最終比較候補は1～3件とする。

## 最終青へ渡す情報

- 議題
- 判断基準：最大4件
- 確定候補：最大3案
- 主要リスク：最大3件
- 主要便益：最大2件
- 不足情報：最大3件
- JavaScriptが作成したアクション候補：最大6件

次は渡さない。

- 除外案
- 緑の組合せメモ
- 黒の対応策
- 黄の戦略的機会
- 赤の関係者別結果
- 全帽子の生JSON

## 最終青のモデル出力

```json
{
  "decisionType": "pilot",
  "selectedIdeaId": "G-003",
  "ideaEvaluations": [
    {
      "ideaId": "G-003",
      "feasibility": 4,
      "recommendationScore": 5,
      "mainReason": "既存施設の余力不足を補える。",
      "mainRisk": "委託条件の調整が必要。"
    }
  ],
  "keyReasons": [
    "新たな大型施設を整備せず着手できる。",
    "処理安定性を高められる。"
  ],
  "selectedActionIds": [
    "ACT-G003-PILOT"
  ]
}
```

案名、概要、必要条件、行動本文はモデルに再生成させず、JavaScriptが元の緑案・アクション候補から復元する。

## コンテキスト予算

`measureContextUsage()`でSchemaを含む使用量を測定する。

- 25%以下：normalで実行
- 25%超：compactへ切替
- compactでも35%以上：実行停止

compactでも候補案は削除せず、リスク・便益・不足情報・アクション候補の件数を減らす。

## 保存

- App：`1.3.0`
- State Schema：`4`
- Prompt：`3`
- Validator：`3`
- localStorage：`sixHatsMeetingsV4`

Schema 3以前のデータは移行しない。旧保存領域は削除しない。

## 回帰条件

製品プラスチックのテストで、`G-002 住民インセンティブ制度`を除外した場合、次を満たすこと。

- 最終青候補に`G-002`がない
- 最終青コンテキストに除外案の名称・説明がない
- 黒の対応策や黄の戦略的機会からインセンティブ施策が再流入しない
- 最終青Schemaのenumに`G-002`がない
- 最終表示の案名と行動本文は元データと一致する
