# Schema 4 Lite 設計概要

## 目的

Gemini Nanoへ複雑な出典追跡や自由な最終文書生成を求めず、最大3案の比較・選択へ役割を限定する。

## 責務分担

|---|---:|---:|---:|
| 緑案の発想 | ○ |  |  |
| 問題のある制約・対象外IDの申告 | ○ |  |  |
| 未申告評価の未確認化 |  | ○ |  |
| 初期採否の算定 |  | ○ |  |

## 緑の生成方式

標準実行ではcompact Schemaを使い、性質の異なる3案を生成する。

- 標準実行：compact、3案
- 深掘り：normal、4案
- normal失敗時：compactで1回再試行
- 緑の各attempt：6分でタイムアウト

4案生成は通常経路から外し、ユーザーが明示的に深掘りした場合だけ使用する。

## concern-only評価

緑は全制約・全対象外事項を列挙しない。問題のあるIDだけを返す。

```json
{
  "constraintConcerns": [
    {
      "constraintId": "C-002",
      "status": "violates"
    }
  ],
  "outOfScopeConcerns": []
}
```

モデルが返さなかったIDは、JavaScriptで次のように保存する。

```json
{
  "status": "unknown",
  "note": "no_concern_reported"
}
```

これは「制約を満たす」「対象外と無関係」を意味しない。適合未確認として候補選択の初期値を`conditional`にする。

## 緑案の採否

各案は次の状態を持つ。

- `include`：最終青へ渡す
- `conditional`：条件付き候補として渡す
- `exclude`：最終青へ渡さない

初期状態は制約・対象外評価から決定する。

- `violates`または`conflicts`：`exclude`
- 明示的な`unknown`、`possibly_conflicts`、または`no_concern_reported`：`conditional`
- 明示的に問題なしと確認できた旧形式データ：`include`

ユーザーは初期状態を変更できる。最終比較候補は1～3件とする。

## 可逆的な着手候補

`pilotMethod`には、ヒアリング、机上確認、試験搬入、小規模実証など中止・見直し可能な検証行動を要求する。

次の文言を含む場合は、そのまま最終青へ渡さない。

- 契約・契約締結
- 発注・購入
- 設備整備・施設建設
- 本格導入・全面導入・全域導入・正式導入

JavaScriptは次のような確認行動へ置き換える。

```text
「候補案」の実施可能性、費用、受入条件をヒアリングまたは小規模試験で確認する
```

各最終候補にはnormal／compact双方で最低1件のアクション候補を確保する。

## 最終青へ渡す情報

- 議題
- 判断基準：最大4件
- 確定候補：最大3案
- 主要リスク：最大3件
- 主要便益：最大2件
- 不足情報：最大3件
- JavaScriptが作成したアクション候補：最大6件

次は渡さない。

- 除外案
- 緑の組合せメモ
- 黒の対応策
- 黄の戦略的機会
- 赤の関係者別結果
- 全帽子の生JSON

## 最終青のモデル出力

```json
{
  "decisionType": "pilot",
  "selectedIdeaId": "G-003",
  "ideaEvaluations": [
    {
      "ideaId": "G-003",
      "feasibility": 4,
      "recommendationScore": 5,
      "mainReason": "既存施設の余力不足を補える。",
      "mainRisk": "委託条件の調整が必要。"
    }
  ],
  "keyReasons": [
    "新たな大型施設を整備せず着手できる。",
    "処理安定性を高められる。"
  ],
  "selectedActionIds": [
    "ACT-G003-PILOT"
  ]
}
```

案名、概要、必要条件、行動本文はモデルに再生成させず、JavaScriptが元の緑案・アクション候補から復元する。

## コンテキスト予算

最終青では`measureContextUsage()`でSchemaを含む使用量を測定する。

- 25%以下：normalで実行
- 25%超：compactへ切替
- compactでも35%以上：実行停止

compactでも候補案は削除せず、リスク・便益・不足情報・アクション候補の件数を減らす。

## 保存・診断

- App：`1.3.0`
- State Schema：`4`
- Prompt：`3`
- Validator：`3`
- localStorage：`sixHatsMeetingsV4`

Schema 3以前のデータは移行しない。旧保存領域は削除しない。

成功・失敗・中止・タイムアウトの各attemptに、実時間、Prompt長、応答長、コンテキスト測定値、Schemaバリアント、エラーを保存する。

## 回帰条件

製品プラスチックのテストで、`G-002 住民インセンティブ制度`を除外した場合、次を満たすこと。

- 最終青候補に`G-002`がない
- 最終青コンテキストに除外案の名称・説明がない
- 黒の対応策や黄の戦略的機会からインセンティブ施策が再流入しない
- 最終青Schemaのenumに`G-002`がない
- 最終表示の案名と行動本文は元データと一致する
- 標準緑はcompact・3案で開始する
- 懸念未申告を制約適合と断定しない
- 契約・全面導入など不可逆なアクションを最終青へ渡さない
