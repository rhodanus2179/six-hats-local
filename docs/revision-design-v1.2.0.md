# 6色思考会議 v1.2.0 改修設計概要

## 目的

v1.2.0では、Chrome Built-in AIを用いた7帽子の生成処理を、再現性・監査性・耐障害性を備えた意思決定ハーネスへ発展させる。

## 主要要件

- BUILD、Prompt、Schema、Validatorの版管理
- `runId`と`attemptId`による実行ログ分離
- 帽子開始・完了・失敗時の自動保存
- 中断した帽子からの再開
- 非ストリーミングの処理フェーズ・経過時間表示
- 白い帽子の入力事実をJavaScriptで決定論的に作成
- 関係者、制約、判断基準、対象外事項のID管理
- 警告の`info`、`review_required`、`blocking`分類
- 表示・移行・生成テストとPASS／FAILレポート

## 出力予算

### 赤い帽子

| 関係者数 | Schema | 処理 |
|---:|---|---|
| 1～6 | `normal` | 期待、不安、直感、伝達上の注意 |
| 7～10 | `lean` | 感情傾向、主要懸念、直感、伝達上の注意 |
| 11以上 | `core` | 中核6件を個別分析し、残りを集約 |
| 出力超過 | `compact` | 主要懸念、直感、伝達上の必要へ縮小 |

関係者名はAIに再生成させず、`S-xxx` IDで対応させる。

### 緑・最終青

緑は標準4案、最終青は標準3案を上限とし、出力超過時は小型Schemaへ切り替えて1回だけ再試行する。最終青は緑案IDを参照し、説明の重複生成を抑える。

## 保存・再開

実行中のPrompt APIセッションそのものは復元しない。ページ再読込時には実行中だった帽子を`interrupted`へ変更し、その帽子から再実行する。

## テストモード

- 表示テスト：保存済み結果をそのまま表示し、AIを呼び出さない
- 移行テスト：旧SchemaをSchema 3へ変換し、差分と警告を確認する
- 生成テスト：入力と期待条件から7帽子を再生成し、PASS／FAILを判定する

## 非目標

- `promptStreaming()`の再導入
- クラウドLLMへのフォールバック
- temperatureの明示指定
- 全関係者の複数バッチ詳細分析
- 判断基準の自動加重スコアリング

## 受入条件

- 画面、保存JSON、ログのバージョンが`1.2.0`で一致する
- 1実行を一意の`runId`で追跡できる
- 帽子単位で自動保存・再開できる
- 赤・緑・最終青が出力予算に従う
- 出力上限超過時にcompact Schemaへ切り替わる
- 制約・対象外事項の評価漏れを検出できる
- blocking警告では必ずワークフローを停止する
- `npm test`の静的チェックが通過する
