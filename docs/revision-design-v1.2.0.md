# 6色思考会議 v1.2.0 改修設計概要

## 目的

単一HTMLだったアプリを責務別に分割し、ローカル起動の手軽さを維持しながら、生成の再現性、監査性、耐障害性を高める。

## 主な改修

- `index.html`、CSS、設定、状態、検証、AI、ワークフロー、UI、保存、テストを分割
- `runId`による実行ログの分離
- 帽子単位の自動保存と中断再開
- 非ストリーミングでの処理フェーズ・経過時間表示
- 白い帽子の入力事実をJavaScriptで決定論的に生成
- 赤・緑・最終青の出力予算管理
- 出力上限超過時のコンパクト再試行
- 制約・対象外事項のID追跡
- 警告の重大度分類
- 表示・生成・移行を区別したテストハーネス

## 緑案の結論適格性

緑の帽子は自由な発想を維持するため、入力制約に抵触する案も生成し得る。最終青へ渡す前に、ハーネス側で各案を次のとおり分類する。

| 状態 | 判定条件 | 最終青での扱い |
|---|---|---|
| `eligible` | 評価済み制約を満たし、対象外事項へ抵触しない | 結論候補として利用可能 |
| `conditional` | 制約評価が不明、または対象外事項との関係が未確定 | 要確認警告付きで利用可能 |
| `excluded` | 1件以上の制約が`violates`、または対象外事項が`conflicts` | 最終青の入力とSchemaから除外 |

除外案については、プロンプト指示だけに依存せず、次の決定論的な防御を行う。

1. 最終青へ渡す緑案一覧から除去する
2. 最終青の`responseConstraint`が許可する緑案IDから除去する
3. 最終出力が除外案IDを参照した場合は意味検証エラーにする
4. 最終結論の要約、推奨、比較案、成功条件、次の行動へ除外案名が混入した場合は意味検証エラーにする
5. 推奨ラベルと選択された比較案の名称が一致しない場合は要確認警告にする

## 互換性方針

v1.2以前の会議JSONとの互換性はリリース要件としない。v1.2のデータ構造を現行の契約とする。ただし、Chromeで`index.html`を直接開く運用は維持する。

## 検証

`npm test`では次を確認する。

- 責務別JavaScriptファイルの存在と構文
- `index.html`のclassic script読込
- CSSの主要構造
- 制約違反案が`excluded`になること
- 除外案が最終青のSchemaコンテキストから消えること
- 除外案IDと案名が最終結論へ混入した場合に拒否されること
